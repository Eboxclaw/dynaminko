# Agent runtime audit — 2026-09-24

Evidence boundary: current `origin/main` (`3b3e7af`) was cloned into `/private/tmp`, with no reuse of the user's browser profile, model cache, or chat storage. Unit tests, type checking, production build, and Chromium UI checks ran there. Local-model answer quality was not benchmarked because this clean runner intentionally had no model weights.

## Confirmed findings

1. **The localhost reload report had a reproducible SSR cause.** `/agents` kept `validateSearch` in its lazy module. The server rendered no selected rail while hydration selected `model`, producing a React hydration mismatch on each fresh load. Search validation and metadata now live in the eager `agents.tsx` route shell, matching the existing Trade/Settings/Earn design.
2. **A running turn could cross a chat boundary.** Session buttons stayed active while asynchronous routing or generation still held callbacks that append messages. Session switching is now locked for the full submitted operation, including the routing work before model generation. A same-tick Send → New regression run verifies the guard.
3. **Session-only diagnostics were not session-only.** The transcript changed, but context ledgers, completed perf traces, raw output, and decide picks survived. Session changes now reset all of those surfaces; runtime-wide model/prewarm state remains shared intentionally.
4. **Native-call recovery exceeded the turn allowlist.** A tool-trained model could emit a catalogue tool from its final answer and the recovery path could execute it without the standard write approval path. Recovery now resolves only against the per-turn allowlist. Read/compute calls may run; write-capable calls only create an approval card.
5. **The portfolio advice fallback was unreachable.** `isPortfolioStatusQuery()` rejected advice before `suppressedAdviceRead()` tested it together with an advice marker. A shared status-shape predicate now separates domain detection from the advice gate.
